# Database — 2021-h2

## Chainswap — Chainswap_exp1.sol
- Date/Chain/Class: 2021-07 / Ethereum mainnet / access-control (broken signature verification)
- Mechanics: The deployed `receive()` on Chainswap's bridge proxy checked ECDSA signature validity and signer quota but, unlike the intended source, did not enforce `require(signatory == signatures[i].signatory)` — i.e. the recovered address was never compared against the claimed signatory. The attacker passed 3 real signer addresses with arbitrary (v,r,s) values as the signatories and withdrew 19,392,277,118,050,930,170,440 units of the bridged token with no valid signature. The PoC replays exactly that call against the proxy at block 12,751,487.
- Lesson: When auditing signature-gated bridges, verify the recovered signer is checked against the claimed signatory on the deployed bytecode, not just in the source repo.

## Chainswap — Chainswap_exp2.sol
- Date/Chain/Class: 2021-07 / BSC / access-control (broken signature verification)
- Mechanics: Same missing-signer-check flaw in a second Chainswap deployment (proxy 0x0891...3466). A single Signature struct naming signatory 0xF1790A... and arbitrary (v,r,s) is accepted because the contract never proves the recovered address equals the named signatory; the attacker mints 500,000,000,000,000,000,000,000 tokens to himself via `receive()`.
- Lesson: A signature-verification bug cloned across deployments multiplies losses — hunt for the same vulnerable pattern on every chain a protocol deployed to.

## Levyathan
- Date/Chain/Class: 2021-07 / BSC / access-control (leaked private key)
- Mechanics: The Levyathan team left the deployer's private key (owner of the Timelock controlling the MasterChef) in a public GitHub repo. Using it, the attacker scheduled `transferOwnership(attacker)` through the Timelock, waited the 172,800s delay, executed it, called `recoverLevOwnership()`, and minted 1e26 LEV tokens. Legitimate stakers could no longer withdraw (only `emergencyWithdraw` still worked for some).
- Lesson: Grep a protocol's public repos and CI for private keys/hardhat configs — an exposed privileged key turns any timelock into a self-service treasury drain.

## Cream
- Date/Chain/Class: 2021-08 / Ethereum mainnet / reentrancy (ERC777/ERC1820 tokenReceived callback)
- Mechanics: crETH's borrow path transferred ETH via an ERC777-style `tokensReceived` callback registered through the ERC1820 registry. The attacker flash-swapped 500 WETH from the Uni pair, minted crETH, and inside the borrow flow re-entered crETH.borrow during the callback (line 74) and stacked crAMP borrows: accrueInterest then a 19,480,000,000,000,000,000,000,000 crAMP borrow while the collateral check was bypassed mid-callback, converting the AMP to WETH and repaying the flash swap.
- Lesson: Any token that invokes a caller-registered callback during transfer breaks the checks-effects-interactions assumption — audit lending protocols for reentrancy through ERC777/ERC1820 hooks, not just plain ETH callbacks.

## PolyNetwork
- Date/Chain/Class: 2021-08 / Ethereum mainnet / access-control (privileged target via cross-chain message)
- Mechanics: `EthCrossChainManager.verifyHeaderAndExecuteTx` let anyone submit a cross-chain transaction and executed it against any contract, passing `onlyOwner` checks because msg.sender was the manager itself. The attacker pointed `toContract` at `EthCrossChainData` with method `putCurEpochConPubKeyBytes` (encoded as f1121318093), replacing the consensus public keys with attacker-controlled ones; with those keys he then forged headers that made the manager call `unlock` on the AssetProxy, releasing 2,857 ETH (and later the rest of the drained assets).
- Lesson: Cross-chain message executors must whitelist which target contracts and method selectors a message may invoke — the privileged caller's own identity must never be the only access control.

## Popsicle
- Date/Chain/Class: 2021-08 / Ethereum mainnet / logic (fee-accounting / reward-debt error)
- Mechanics: Popsicle's SorbettoFragola vaults tracked fee entitlement via per-share-paid markers that were not correctly reset when LP shares moved. The attacker Aave-flash-loaned six assets, deposited into eight vaults, shuffled the LP tokens between two helper TokenVaults calling `collectFees(0,0)` at each hop, then claimed `collectFees` for each holder — collecting the same accrued protocol fees multiple times from each vault before selling the assets back.
- Lesson: When shares change hands, reward/fee debt must be settled on BOTH sides of the transfer — a missing `updateFees` on transfer is an invitation to multi-claim.

## WaultFinance
- Date/Chain/Class: 2021-08 / BSC / oracle manipulation (stake-driven price inflation)
- Mechanics: The attacker flash-swapped nearly the whole WUSD reserve from the WUSD/BUSD pair, redeemed WUSD for USDT and WEX through WUSD Master, flash-swapped USDT from the WBNB/USDT pair, then converted USDT→WEX and staked WEX into the Master 68 times — each stake pumped the WEX price the protocol used, inflating the attacker's WEX holdings. Selling the inflated WEX back for USDT repaid both flash swaps with a large BUSD profit left over.
- Lesson: When a protocol derives a token's price from its own stake/redeem state, a flash-loan can push that price arbitrarily — never price collateral from a manipulable in-protocol mechanism.

## XSURGE
- Date/Chain/Class: 2021-08 / BSC / reentrancy (sell-state not updated before external call)
- Mechanics: The Surge token's `sell()` sent BNB to the seller before updating the token supply/price state. The attacker flash-loaned 10,000 WBNB, bought Surge with the BNB, then called `sell()` seven times; each sell's BNB payout triggered the attacker's `receive()` which re-bought Surge mid-execution (6 times), so every subsequent sell computed its payout on stale state and yielded more BNB than the tokens were worth. He repaid 10,030 WBNB and banked the difference.
- Lesson: Token contracts that pay out before updating state are reentrancy-ripe: check every `buy`/`sell` for effects ordered after external value transfers.

## DaoMaker
- Date/Chain/Class: 2021-09 / Ethereum mainnet / access-control (unprotected initializer)
- Mechanics: The vesting contract's `init()` lacked an initialized/onlyOwner guard, so anyone could re-initialize the already-deployed contract and set themselves as owner with a vesting schedule (100% released). The attacker called `init()` with himself as beneficiary and then `emergencyExit()`, draining DERC and, in variants, CAPS/CPD/SHO from four vesting pools (~$7M).
- Lesson: Always check `initializer` modifiers on deployed contracts — "initialized once at deployment" is an invariant, not a given.

## Nimbus
- Date/Chain/Class: 2021-09 / Ethereum mainnet / logic (broken K invariant: 10000 vs 1000 constants)
- Mechanics: The Nimbus swap pair computed `balanceAdjusted = balance*10000 - amountIn*15` but compared the product against `reserve0*reserve1*1000**2`, a 100x laxer K-check than intended. Flash-swapping 99% of the pair's USDT and repaying only 1/10 of it (via the `NimbusCall` callback) still satisfied the invariant, so the attacker walked away with ~90% of the borrowed USDT.
- Lesson: When reviewing forks of UniswapV2, diff every constant and operator in the K-check against the original — off-by-one-zero constants are instantly exploitable.

## NowSwap
- Date/Chain/Class: 2021-09 / Ethereum mainnet / logic (broken K invariant: 10000 vs 1000 constants)
- Mechanics: NowSwap's unverified NWETH/NBU pair carried the same 10000-vs-1000 inconsistency: the fee-adjusted product check demanded 100x less than it should. The attacker flash-swapped 99% of the pair's NBU, and in the fallback repaid only 10% of his NBU balance; the lax invariant accepted it, netting ~90% of the pool's NBU.
- Lesson: Unverified-but-used pair contracts are prime targets — a constant-consistency diff of the swap invariant is a 5-minute check that finds 7-figure bugs.

## Sushimiso
- Date/Chain/Class: 2021-09 / Ethereum mainnet / logic (msg.value reuse inside batch)
- Mechanics: MISO's DutchAuction `batch()` executed an array of calls while each sub-call received the single `msg.value` sent to the batch. The attacker sent 100 ETH with five `commitEth` calls packed into the batch, so the auction credited 500 ETH of commitments for 100 ETH sent, and after the auction he withdrew most of the ETH pool via refunds.
- Lesson: Batch/delegatecall helpers must either forward value exactly once or reject value-bearing sub-calls — track where msg.value lands in every multi-call primitive.

## ZABU
- Date/Chain/Class: 2021-09 / Avalanche / access-control (missing user-balance check in withdraw)
- Mechanics: ZabuFarm's `withdraw` did not verify that the requested amount matched the caller's staked position — the attacker's helper deposited a little SPORE then called `withdraw(38, SPORE.balanceOf(farm))` to pull the farm's ENTIRE SPORE balance. Wrapping this in flash-swaps on two Pangolin SPORE pairs and repeated deposit/withdraw loops, he drained the farm's SPORE, farmed ZABU rewards, and sold ZABU for WAVAX profit.
- Lesson: Any farm `withdraw` that reads the pool balance instead of the user's staked mapping is a full-drain waiting to happen — check the withdrawal amount source.

## Cream_2
- Date/Chain/Class: 2021-10 / Ethereum mainnet / oracle manipulation (vault share-price donation)
- Mechanics: CREAM valued crYUSD collateral via the yUSD vault's `pricePerShare`. The attacker Maker-flash-loaned 500M DAI into yUSD collateral and Aave-flash-loaned 524K ETH into crETH collateral, then cycled borrow/mint of yUSD→crYUSD between two contracts to inflate the recorded collateral. In the final step he withdrew yUSD and donated the underlying yDAI/yUSDC/yUSDT/yTUSD back to the vault (`transfer(yUSD, totalAssets)`), roughly doubling `pricePerShare` — doubling his collateral value — then borrowed every crToken market dry (~$130M).
- Lesson: Any lending market whose oracle reads a vault's `pricePerShare` is vulnerable to donation attacks — price must be derived from externally verifiable sources, never from manipulable internal state.

## IndexedFinance
- Date/Chain/Class: 2021-10 / Ethereum mainnet / price manipulation (stale weights + gulp donation)
- Mechanics: The DEFI5 index pool priced spot swaps from denormalized weights that were out of sync with the pool's actual token set. The attacker flash-loaned UNI/AAVE/COMP/CRV/MKR/SNX, called `reindexPool`, then swapped each loaned token for the pool's cheapest token (tokenOut) at the stale-weight prices, minted DEFI5 pool tokens with that cheap token, flash-borrowed 220K SUSHI and donated it to the pool followed by `gulp(SUSHI)` — raising the pool's recorded value — and finally `exitPool`'d his DEFI5 for a proportional slice of the now-inflated pool.
- Lesson: Weight-based pools must recompute weights and total supply atomically with every state change — stale weights plus a balance-syncing `gulp` gives attackers a mint-and-exit arbitrage.

## Mono
- Date/Chain/Class: 2021-11 / Ethereum mainnet / price manipulation (self-swap tokenIn == tokenOut)
- Mechanics: MonoX's `swapExactTokenForToken` allowed tokenIn == tokenOut and updated the input token's reserve before computing the output price, so swapping MONO→MONO raised the MONO price on each iteration. The attacker removed other users' MONO/USDC liquidity, added a little of his own MONO, swapped MONO for MONO 55 times to pump its price ~2^55 times, then swapped the inflated MONO for ~4B USDC from the pool.
- Lesson: Same-token swaps must be rejected outright — any AMM that credits the input before pricing the output turns tokenIn==tokenOut into a free price pump.

## Ploutoz
- Date/Chain/Class: 2021-11 / BSC / oracle manipulation (spot-price collateral valuation)
- Mechanics: Ploutoz's lending market valued DOP collateral at the live DEX spot price. The attacker Pancake-flash-loaned 1,000,400 BUSD, used it to pump the DOP price on both TwindexSwap and PancakeSwap, then borrowed CAKE/DOLLY/WETH/BTCB/USDT/BUSD loans against a few overvalued DOP tokens; he sold part of the DOP back to repay the flash loan and kept the borrowed assets (~$365K).
- Lesson: A lending protocol that appraises collateral with an uncapped spot price of its own reward token is one flash loan away from liquidation-free borrowing.

## Grim
- Date/Chain/Class: 2021-12 / Fantom / reentrancy (depositFor share accounting before transfer settles)
- Mechanics: GrimBoostVault's `depositFor` transferred the LP tokens from the user (triggering the attacker contract's `transferFrom`) BEFORE recording the user's shares. The attacker's fake `transferFrom` re-entered `depositFor` six times passing his own contract as the token (fake transfers that succeed trivially), each minting shares for the same underlying LP deposit; on the last step he deposited the real Spirit LP. `withdrawAll` then redeemed all seven share positions for real LPs, and he removed the flash-loaned BTC/WFTM liquidity with a large profit.
- Lesson: Vault share minting must be the first state change before any token pull — a transfer hook before share accounting lets one deposit mint N shares.

## NerveBridge
- Date/Chain/Class: 2021-12 / BSC / logic (metapool internal accounting desync)
- Mechanics: The attacker flash-loaned 50,000 BUSD from ForTube, swapped to fUSD on Ellipsis, then ran seven cycles of: metaSwapPool.swap(fUSD→Nerve 3-LP), nerve3pool.removeLiquidityOneToken(→BUSD), and metaSwapPool.swapUnderlying(BUSD→fUSD). The metapool's `swapUnderlying` priced BUSD using internal recorded balances that were never synced with the BUSD removed from the underlying pool, so each cycle returned more fUSD than it consumed; the final fUSD→BUSD swap repaid the loan and kept the profit.
- Lesson: Meta-pools wrapping base pools must reconcile their internal balances with the underlying pool after every LP add/remove — a desync between recorded and real balances is a free arbitrage loop.

## Visor
- Date/Chain/Class: 2021-12 / Ethereum mainnet / access-control (fake transfer via untrusted callback)
- Mechanics: RewardsHypervisor's `deposit` pulled the deposit from a caller-supplied `from` address by calling its `owner()` and `delegatedTransferERC20`, trusting the result. The attacker passed his own contract as `from` with `owner()` returning himself and `delegatedTransferERC20` doing nothing, so the hypervisor credited a 1e26-token vVISR position without receiving any tokens — minting value from nothing.
- Lesson: Never trust external `owner()`/transfer callbacks on a user-supplied address — verify token balances actually moved (before/after) when crediting positions.
